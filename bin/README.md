# Capability helper

The separate `armada_model_probe.cpp` is an original MIT analytic capture application using unmodified public AMD FFX C API headers under `include/ffx`. It loads the supplied local provider using restricted DLL search, requires Qualcomm wave64 and performs two bounded synthetic dispatches with explicit unit exposure. Fenced readback checks finite, nonblack and spatially varying RGB independently of API completion. It rejects constant red fallback output. Checker correlation is diagnostic only, with no acceptance threshold until target calibration. These checks do not prove correct reconstruction, game rendering or performance. The helper does not hook games, inspect compiled provider internals or embed shader/model material. Capture dumps and generated overrides stay local to the setup job.

Rebuild from the repository root with `clang++ --target=x86_64-w64-windows-gnu -std=c++17 -O0 -static -municode -Wall -Wextra -Werror -Ibin/include/ffx bin/armada_model_probe.cpp -o bin/armada_model_probe.exe -ld3d12 -ldxgi -ldxguid -lole32`. The recorded build used Clang 23.1.3; `armada_model_probe.build.json` records the reviewed hashes and host numeric/negative CLI checks. `armada_model_probe.exe --numeric-self-test` exercises the actual decoding and aggregation code without loading a provider or querying a GPU. Changing a helper requires source review, updated executable pins and fresh target validation.

Setup uses up to four fresh discovery attempts. Each must add at least one exact pinned override before another attempt. Each process has a new prefix, dump folder and report, with shader caching disabled. Only bounded context/dispatch failures with healthy cleanup may contribute captured inputs. Once all four outputs match their pins, a separate fresh run with all overrides must complete both dispatches and pass RGB checks. A successful API report from a discovery run is never sufficient for activation.

`wave_probe.cpp` is original MIT-licensed application code. It queries a Qualcomm D3D12 adapter's wave limits and native 16-bit capability and writes JSON; it contains no game shader, provider, network asset or GPU workload.

Build an x64 Windows PE with Clang and MinGW-w64 headers/libraries, matching the installed Wine/FEX route. A typical cross-build is `clang++ --target=x86_64-w64-windows-gnu -std=c++17 -O0 -static wave_probe.cpp -o wave_probe.exe -ld3d12 -ldxgi -lole32 -luuid`. Supply your toolchain's sysroot/library directories as required. The shipped binary was built with Clang 23.1.3; exact compiler or runtime versions can change its hash. An intentional rebuild needs an updated `PROBE_SHA` in `armada_host.py` and a new verified device capability test.

The MinGW-w64 runtime notices are included in `licenses/COPYING.MinGW-w64-runtime.txt`. The C++ source is included with the plugin for rebuilding. On Armada, Decky's x86 FEX process invokes native helpers through `/proc/self/root/usr/bin` to avoid guest filesystem mapping, then uses the ARM64 Proton runtime in a separate prefix.
